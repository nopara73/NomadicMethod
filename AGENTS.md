# Default delivery

- After completing and validating an implementation, commit, push, and deploy it whenever possible without waiting for another deployment request, unless the user explicitly asks to hold off. Deploy the public web app and install the validated Debug build on the connected phone using the safeguards below.
- Never publish a shared change that has not passed the required Android/web validation. If the phone is unavailable, finish the verified web deployment and report Android as pending; never imply that an unavailable device was updated.
- Coordinate concurrent work before publishing or installing so each deployment comes from one identified, validated commit and preserves unrelated changes.

# Android and web parity

- Explicit owner exception: Oura recovery integration is Android-only, using the phone's Health Connect data automatically, not an optional Nomadic Method feature. Do not add a connection tile, status dialog, opt-in, refresh or disconnect control; Android owns health-data consent. Do not port it to web, add web imports/OAuth, or send health data to a server. Follow `docs/OURA_RECOVERY.md`: the agreed three-way evidence gate replaces only cadence-derived automatic Light, never manual Light or muscle recovery, and insufficient evidence falls back to cadence. Keep native permission, privacy, lifecycle and active-session protections tested; continue validating the unchanged web product and its parity lock.

- Treat the Android app in [`NomadicMethod/`](NomadicMethod/) as the canonical product contract and keep [`web/`](web/) synchronized with it at all times.
- Update both platforms in the same change whenever workout flow, wording, controls, durations, exercise selection, taxonomy, catalog migration, persistence, sounds, colors, or runtime media changes.
- Keep the web catalog and deployable media sourced from the Android runtime assets. Do not maintain a divergent web-only catalog or duplicate media source of truth.
- Platform-specific responsive layout may adapt to the screen, but the visible product flow, available actions, state transitions, and outcomes must remain equivalent.
- Do not refresh [`web/mobile-parity.json`](web/mobile-parity.json) merely to make the parity check pass. First port and review every affected Android behavior in the web implementation, then refresh the lock.
- Extend the cross-platform contract tests whenever a new shared behavior or migration rule is introduced, so future Android-only changes fail web validation.
- Before considering a shared change complete, run the Android tests, the web tests, and the production web build. If either platform cannot be synchronized and validated, report the work as incomplete and do not publish it.
- Treat `https://nopara73.github.io/NomadicMethod/` as the public web deployment; localhost URLs are previews only. After publishing, verify the completed GitHub Pages run and confirm that the public URL serves the current catalog and hashed assets before reporting the release as deployed.

# Physical Android device installs

- Always install a debuggable `Debug` build on the user's connected phone. Release APKs may be built as distribution artifacts, but must not be installed on that phone.
- Replace the existing package in place so persisted workout state survives. Never uninstall the app or clear its data as part of deployment.
- Before switching an existing installation to Debug, verify that the installed APK and Debug APK have the same signing certificate. After installation, verify that `run-as com.local.nomadicmethod` succeeds; an install is not complete merely because `adb install` returned success.

# Exercise selection guidelines

- An unfinished session never expires. Cold opening, closing, backgrounding, or elapsed calendar time must not finalize, discard, restart, or silently replace it. Restore Ready as well as movement/rest checkpoints; pause timers on cold reopen, including after abrupt process death, and retain the original session/history and frozen automatic-Light decision. No time outside Nomadic Method counts as performed work.
- Workout settings allow changing total duration and explicitly ending the session, not restarting it. Duration edits retain completed selections and the whole current atomic selection, including its existing sets, then use the normal planner for the remaining budget; retain stable round/slot IDs across resolution changes. Never erase completed work or cut a side/direction sequence to fit a shorter duration. Persist each duration change and its plan in history. End session uses a stop icon and confirmation, archives actual prior work as interrupted, preserves earned Keeps/scores/recovery, and returns to setup without starting another session. Never invent downvotes or completed blocks, and never call this explicit ending path from app lifecycle handlers.

- Owner-accepted coverage exceptions (12 September 2026): omit `r15.scapular-chest-breathing` while Insect is on; omit `r15.shoulder`, `r20.shoulder-adduction-extension`, `r30.rotator-cuff` and `r30.shoulder-adductors-extensors` while both Insect and Hard Floor are on; omit `r30.breathing-muscles` while Insect and either Silence or Shy are on. These exact remaining gaps do not require new exercises and do not block release. Use the same exceptions on Android and web, redistribute complete rounds to preserve the selected duration, and retain completed work across modifier changes. All other availability and complete-lineup checks still apply. Do not resume sourcing exercises to fill these accepted exceptions unless the owner explicitly requests it.

- Select real, established, worthwhile exercises first; never invent movements, filler, or artificial variations.
- Accept an exercise only when an ordinary person can immediately copy it for 45 seconds from its plain name and final silent demonstration. Any uncertainty means rejection.
- Require feet-only ground contact, ordinary-shoe compatibility, and a 2 m × 2 m maximum area. Exercises require zero equipment unless they genuinely require either an ordinary stable wall and are explicitly classified `WallRequired`, or a physical mirror and are explicitly classified `MirrorOnly`; those exercises must remain unavailable while their equipment is off. Quiet execution is required whenever the default-on Silence modifier is enabled; established naturally noisy movements may be admitted only when their sound is the ordinary result of execution and they remain excluded by Silence.
- Require exact human media showing the complete natural movement at normal speed. Reject approximate, composited, obscured, mismatched, or misleading demonstrations.
- Keep non-locomotor demonstrations planted in place. Advancing, retreating, or crossing the room is acceptable only when travel is an intrinsic, plainly named part of the exercise.
- Allow similar exercises.
- Derive timing, sides, directions, name, and muscle associations from the demonstrated movement—never force the demonstration to fit predetermined metadata.
- Treat canonical muscle associations as training claims, not an inventory of every muscle that activates. `Primary` is the movement's main trained target and, for demand-2 work, the local muscle whose force or fatigue makes the round hard. `Secondary` means that muscle receives a meaningful trainable stimulus during the complete 45-second block; ordinary bracing, balance, posture, and incidental stabilization must be omitted. Never add a secondary association merely to satisfy coverage, workload balance, or quota validation.
- Never add a muscle-specific scheduler bonus to hide a catalog or anatomy blind spot. Correct the metadata and add genuine direct work so the existing generic selection and balancing rules can act on truthful inputs. Every canonical muscle group must retain at least one genuine primary session movement; secondary coverage never satisfies that invariant. `tools/ExerciseSecondaryTrainingClaims.psd1` is the exact catalog-wide allowlist for secondary training claims, and catalog generation must reject any drift from it.
- Assign muscle groups only after approval; coverage requirements never justify admitting a weak exercise.
- When an anatomy correction makes an existing exercise invalid for a saved fine-muscle slot, migrate only that impossible slot selection and Keep. Preserve the exercise's persisted score and every Keep that remains anatomically valid in another slot; a metadata correction is not a new exercise identity.
- For every pair of workout modifiers and each real UI state, require nonempty approved selectable availability in every applicable broad and fine muscle bucket. Availability is one real choice, not a five-choice population quota. Keep meaningful breadth in broad rounds: the existing 50% trained-muscle path or a reviewed dynamic regional compound. Upper-limb compounds require direct shoulder and elbow training with a proximal primary target; broad torso compounds require direct anterior and posterior trunk training with a trunk primary target. Static poses and isolated wrist, neck or shoulder drills never qualify through the compound path, and every distinct member of a qualifying atomic sequence must qualify. Keep all fine-bucket rules, truthful primary and meaningful secondary claims, and complete atomic sides/directions. Separately require a complete atomic lineup within the selected duration; different slots need not use different movements. Prefer the existing distinct lineup when available, and allow a complete movement to repeat in independently tracked slots when necessary. Never count repeated rounds or aliases as extra catalog identities. An isolated wrist, neck or shoulder drill cannot replace a broad upper-body round. A restrictive modifier off relaxes its predicate; Mirror off excludes only MirrorOnly exercises. Eligible Agnostic exercises count whether Mirror is off or on. Preserve compact/tall equipment predicates. Keep validation quadratic in modifiers and reject every live availability or complete-lineup deficit. Do not add scope confirmations, reduced-workout choices or grouping diagnostics to the UI.
- In Insect mode, `PelvicFloorAndPerineum` is structurally unavailable because honest isolated pelvic-floor work cannot also supply the visible continuous whole-body movement Insect promises. `IntrinsicHand` is unavailable only while Wall is off; genuine wall-based hand work restores it when Wall is available. Keep ordinary non-Insect coverage and never invent secondary claims or unrelated marching combinations to erase these exact structural exceptions.
- Require nonempty HardFloorCompatibility.Compatible availability for applicable regions and fine buckets. There is no minimum for HardFloorCompatibility.Incompatible populations: a floor-safe movement does not require a soft-floor-only counterpart. Hard Floor off admits both truthful categories. Preserve the physical classification rules, equipment gating and the exact Insect structural exceptions.
- Report demand-0 and demand-2 inventories across the existing single/pair profiles and broad body regions as diagnostics, not admission quotas or release gates. Preserve fixed truthful ratings: a demand-0 sequence requires every distinct member to be demand 0; a demand-2 regional sequence requires a demand-2 member with its primary muscle in that region. Count SessionMovementId once. Never add filler, alter anatomy or rerate an exercise to fill an intensity category. Light ranking and actual workout coverage remain unchanged.
- Treat mirror relationship, coverage, BenefitsGreatly criterion populations and percentage-based modifier materiality as audit results, never fixed minimums, targets or release gates. Keep them visible in the diagnostic ledger. Retain exact schema and catalog partition validation. Every greatly-benefited exercise must fit the narrow audited criteria in tools/ExerciseMirrorRelationships.psd1; ordinary optional form checking does not qualify. Preserve truthful minimum mirror coverage, equipment gating and preference behavior. Review membership changes semantically and update Android/web expectations deliberately.
- Keep Wall outside pairwise, per-muscle, duration, and materiality quotas. Require at least 20 distinct approved `WallRequired` session movements globally; sides, directions, blocks, sets, aliases, and renamed duplicates never increase that count.
- Keep Light outside pairwise and materiality checks as a modifier axis; demand inventories are reported by the separate muscular-demand audit above. Light is a session-scoped ranking control, not an exercise-compatibility predicate: it first maximizes atomic sequences whose every distinct member has `muscularDemand = 0`, then lets saved score, Keep, recovery, and equipment preferences arbitrate among those light choices. Automatic Light is based on completed regular work, not a fixed number of sessions or days: each completed non-Light 45-second block contributes one nominal workout minute, including completed blocks in interrupted sessions. Aggregate every session by the block's local calendar date, cap each date at 60 credited minutes, and require Light for the next workout once consecutive training dates accumulate 180 credited minutes. Ten 3-minute sessions daily reach this after six regular days, not sixty; 60-90 minutes daily reaches it after three. Do not add another hardness weighting or alter scores, Keeps, or muscle recovery. A completed Light workout resets the accumulator only on the following local date, so a token Light workout cannot unlock regular mode again the same day; a complete no-training date also resets it. Automatic Light must be ON and non-interactive before and during the workout when due; manual Light remains optional otherwise. Never persist Light as the next session's physical setup. While Light is OFF, its badge estimates remaining workouts at the currently selected duration (up to 60); hide it whenever Light is ON. Preserve existing history and conservatively support pre-block-history durations and already-inferred legacy training dates without double-counting them. See `docs/MUSCULAR_DEMAND_AUDIT.md` for the exact contract and backward compatibility.
- Separately present the Light tile as ON and temporarily non-interactive when at least 80% of canonical muscles with a currently selectable demand-1 or demand-2 primary exercise have no fresh demanding path. A muscle satisfies this recovery-derived condition only when every demanding category available to it is still recovering: demand 1 uses the rolling 18-hour meaningful-work window and demand 2 uses the rolling 36-hour hard-work window. Recompute this against the current equipment/context modifiers and current time. This is presentation of the existing recovery behavior only: never set the Light modifier, change ranking, persist a fake Light session, or count it as a cadence Light day.
- Automatic Light cadence has a completion tolerance: a completed, wholly regular session with at least 85% of its planned blocks completed receives its full planned duration as cadence credit, still capped at 60 minutes per local date. Apply this to existing logs without rewriting them. Below the threshold, in interrupted or in-progress sessions, and in sessions that used Light at any point, count only actual completed regular blocks. Keep actual blocks on their own dates and add only the top-up on the recorded completion date. Never fabricate logged blocks, change scores or Keeps, or update muscle-recovery timestamps for this credit. Preserve this rule in Android, web, and the instant startup controls; the 53/60, 56/60, 55/60 history must make Light due and locked ON.
- Locked Light remains ON but accepts taps solely to show the existing modifier animation with the exact headline `rest, you must` and a brief smaller reason underneath. Explain the actual locking decision; Android Oura reasons show only its recorded warning signals, never invented measurements or a newer decision substituted for a frozen workout. Apply this to automatic-cadence and recovery-derived locks before and during workouts, including web instant startup; Oura itself remains Android-only. Do not disable the tap target itself or let an explanation tap change modifiers, prepare a new lineup, or write workout state. Manual Light remains freely toggleable when neither lock applies.
- Review the final packaged exercise—including crop, loop, hold frame, and every timer phase—inside an actual workout before promotion.
- Demonstrations must show an actual person except when the trained action is internally invisible and an exterior view would be inherently unverifiable. That narrow exception requires an authoritative medical anatomical visualization of the exact action, an explicit entry in `VerifiedExerciseDemos.psd1`, and the same final-media review as human footage; it never permits generic diagrams or synthetic approximations.
